# AGENTS.md — AllNote

AllNote produces **Danish gymnasium factsheets**: dense A4 reference
sheets, one topic per sheet, in a single house style. Agents write **content
only**. `build.py` owns layout and turns HTML into PDF.

## Division of labour

| Who | Owns |
| --- | --- |
| You (agent) | `content/Subject/Name.html` — the content |
| `build.py` | styling injection, page furniture, PDF rendering |
| `factsheet.css` | the visual design (do not edit unless asked) |
| `tools/diagram.py` | SVG diagrams (you run it, never hand-write huge SVGs if the tool can do it) |

Never write, edit or delete a `.pdf` by hand. Never put CSS, `<script>`,
`<link>` or external images in a sheet. Never add a source apparatus — no
literature lists, no links, no "læs mere". Naming the material itself
(theorists, schools, works under analysis) is content, not a reference; see
§ 4.

---

## 1. Add or edit a sheet

```
content/Subject/Sheet_name.html          ->  dist/Subject/Sheet_name.pdf
content/Subject/Group/Sheet_name.html    ->  dist/Subject/Group/Sheet_name.pdf
content/Matematik/Retvinklede_trekanter.html
content/Dansk/Sprog/Ordklasser.html
```

* HTML lives only in `content/`, PDFs only in `dist/`. Never write into `dist/`.
* One folder per subject under `content/`, named as the Danish school subject
  (`Matematik`, `Fysik`, `Kemi`, `Biologi`, `Dansk`, `Historie`, `Samfundsfag`, …).
  Create the folder if the subject is new.
* File name = the sheet title with spaces as underscores. Letters, digits and
  underscores only. Underscores become spaces in the PDF footer.
* Sheets live directly in the subject folder, or **one** group folder deeper
  (`Dansk/Sprog/Ordklasser.html`). Two levels or more are rejected by `build.py`;
  `dist/` mirrors the same folder structure.
* One HTML file = one PDF. Keep a topic together instead of splitting it.

Build just your sheet:

```bash
python build.py Matematik
python build.py Dansk/Sprog
python build.py content/Matematik/Retvinklede_trekanter.html
```

The PDF appears in the matching folder under `dist/` (`dist/Matematik/`,
`dist/Dansk/Sprog/`). `build.py` skips up-to-date files;
`--force` rebuilds everything; no arguments builds every sheet.

## 2. HTML skeleton

```html
<!doctype html>
<html lang="da">
<head>
<meta charset="utf-8">
<title>Retvinklede trekanter</title>
</head>
<body>

<h1>Retvinklede trekanter</h1>

<h2>Pythagoras</h2>
<div class="box rule">
  <span class="label">Sætning</span>
  <div class="formula"><math>…</math></div>
  <p class="where">a, b: kateter · c: hypotenuse</p>
</div>

</body>
</html>
```

* The `<h1>` is the only page title. Do **not** write the subject, the date or
  a page number anywhere — the footer adds them.
* Do not add `<style>`: use the classes below. Do not add `<script>`.
* Write valid, well-formed HTML. Uppercase Æ Ø Å in text, `&nbsp;` between a
  number and its unit (`9,82&nbsp;m/s²`).

## 3. House classes

| Class / element | Use |
| --- | --- |
| `.box` + `.label` | framed fact: definition, rule, example |
| `.box.rule` | the key result of the section (thicker accent bar) |
| `.box.warn` | pitfalls and typical mistakes (red bar) |
| `.box.note` | asides, conditions, "gælder kun når…" (grey bar) |
| `.formula` | centred display formula |
| `.formula.left` | left-aligned formula block |
| `.where` | small grey line under a formula: symbols, units, conditions |
| `.grid2` / `.grid3` | equal-width columns for boxes, tables, figures |
| `.cols2` | two-column text flow for long reference lists |
| `.fig-flex` | two diagrams side by side |
| `table`, `table.compact` | data tables; `th`, `td`, `td.num` (right-aligned numbers) |
| `figure`, `figcaption` | diagram plus caption (generated by the diagram tool) |
| `ul.tight`, `ol.tight` | lists with no extra spacing |
| `dl.kv` | `dt`/`dd` term–definition pairs in two columns |
| `.tag` | small grey label, e.g. `EKSAMEN` |
| `.mono` / `code` | code, syntax, file names |
| `.chem` | chemical formula wrapper |
| `.small`, `.muted`, `.center`, `.nowrap`, `.keep` | small utilities; `.keep` prevents a page break inside |

Headings: `h1` title, `h2` main sections (uppercase, accent), `h3` sub-sections,
`h4` run-in label. Do not skip a level.

## 4. Content standard

**Language and level**

* Danish, gymnasium terminology, correct symbols and units.
* Aim high: include the exact conditions of validity, the general case, and
  the non-obvious special case. Prefer *for* advanced over *for* simple.
* No fluff. Delete every sentence that does not carry information:
  * ✗ "I dette dokument vil vi se på…", "Det er vigtigt at huske…", "Som vi har set…"
  * ✓ "Gælder kun for konstante hastigheder."
* Telegraphic style is correct here: definition → formula → example → pitfall.
  Full sentences only where the logic needs them.

**Structure of a sheet**

1. `h1` title.
2. 3–7 `h2` sections, each a keyword the reader can scan for
   (`Definitioner`, `Sætninger`, `Kraftmodeller`, `Regneeksempel`,
   `Faldgruber`).
3. At least one table **or** diagram; most sheets need both.
4. At least one worked example with numbers and units.
5. One `.box.warn` with the mistakes students actually make.

**Length budget**

* Target 1 page, acceptable 2, hard maximum 3.
* When it does not fit: cut content, merge sections, tighten wording.
  Never shrink type, never use a smaller margin. The type size and margins are
  fixed by the design.

**Never**

* Citation apparatus: no bibliography, no "Kilde:", no URLs, no page
  references, no "læs mere", no publisher, edition or ISBN data.
* But name the material. Theorists, schools, concepts and the works being
  analysed belong in the text: "Barthes' »Forfatterens død« (1967)", "Propps
  31 funktioner", "Aristoteles' peripeti". A name is content when the sentence
  still carries its point for a reader who cannot look it up; it is a citation
  when the point is where the sheet got it from.
* Filler introductions, summaries of what the sheet contains, motivational text.
* Decorative images, icons, emoji, gradients, coloured backgrounds.
* Invented facts or formulas. If a value is uncertain, leave it out.

**Numbers and notation**

* Decimal comma: `3,14`, `9,82 m/s²`.
* Minus sign `−` (U+2212) in formulas, hyphen only in words.
* Multiplication `·` or `\cdot` in MathML, not `x` or `*`.
* Units upright, variables italic, vectors with an arrow.
* Prefixes and units in the same style throughout a sheet.

## 5. Mathematics: MathML only

No LaTeX, no pictures of formulas. Chromium renders MathML natively and the
result is searchable, selectable text.

```html
<!-- a² + b² = c² -->
<math>
  <msup><mi>a</mi><mn>2</mn></msup><mo>+</mo>
  <msup><mi>b</mi><mn>2</mn></msup><mo>=</mo>
  <msup><mi>c</mi><mn>2</mn></msup>
</math>

<!-- fraction -->
<math><mfrac><mi>a</mi><mi>c</mi></mfrac></math>

<!-- square root -->
<math><msqrt><mn>3</mn></msqrt></math>

<!-- F_t = m·g -->
<math>
  <msub><mi>F</mi><mi>t</mi></msub><mo>=</mo><mi>m</mi><mo>·</mo><mi>g</mi>
</math>

<!-- vector F -->
<math><mover accent="true"><mi>F</mi><mo>→</mo></mover></math>

<!-- inverse tangent -->
<math>
  <msup><mi>tan</mi><mrow><mo>−</mo><mn>1</mn></mrow></msup>
  <mo>(</mo><mi>a</mi><mo>/</mo><mi>b</mi><mo>)</mo>
</math>
```

Wrap display formulas in `<div class="formula">…</div>`; inline formulas can
sit directly in a paragraph. Multi-character `<mi>` (e.g. `sin`) is upright
automatically; use `<mi>v</mi>` for variables so they stay italic.

Units are upright text, not a row of variables. Inside math use
`<mspace width="0.25em"/><mtext>m/s²</mtext>`; outside math write
`9,82&nbsp;m/s²`. Never build units from `<mo>/</mo>` and `<mo>·</mo>` — they
are operators and pick up visible spacing (`m / s`).

Two rendering rules that follow from how Chromium draws MathML:

* **No square root in a fraction's denominator.** `<mfrac><mn>1</mn><msqrt>…</msqrt></mfrac>`
  is set in script size: the radicand shrinks to about two thirds and its
  overline passes through it, so the formula looks like a misdrawn fraction.
  Write the expression with a negative power instead —
  `<msup><mrow><mo>(</mo><mn>1</mn><mo>−</mo><msup><mi>v</mi><mn>2</mn></msup><mo>/</mo><msup><mi>c</mi><mn>2</mn></msup><mo>)</mo></mrow><mrow><mo>−</mo><mn>1</mn><mo>/</mo><mn>2</mn></mrow></msup>`
  — or put the root outside the fraction. A root that stands alone renders
  correctly at full size, so `√(2GM/r)` in its own `.formula` block is fine;
  keep the radicand free of nested fractions and write it with a slash.
* **No `<br>` inside a `.formula` block.** A display fraction on the second
  line overlaps the first. Split the calculation into two `.formula` (or
  `.formula.left`) blocks; each gets its own spacing.
* Long inline fractions (`e = (a−b)/(c−d)` in running text) squeeze the line and
  collide with the text above. Put them in a display block, or write them with
  a slash.

## 6. Diagrams

Diagrams are inline SVG, generated with the tool and pasted into the HTML.
Never use `<img>`, never link a file, never paste a bitmap.

```bash
# Cartesian plot
python tools/diagram.py plot --expr "sin(x)" --xmin -6.3 --xmax 6.3 \
    --ymin -1.5 --ymax 1.5 --xlabel "x" --caption "Grafen for f(x) = sin x"

# Several curves with a legend
python tools/diagram.py plot \
    --series "2*x+1|linje" --series "x^2|parabel" \
    --xmin -4 --xmax 4 --ymin -2 --ymax 10

# Free-form drawing from JSON
python tools/diagram.py prim figur.json --caption "Kraftdiagram for en klods"
cat figur.json | python tools/diagram.py prim -
```

The command prints a complete `<figure>` block (SVG + `<figcaption>`). Paste it
where the diagram belongs. `--bare` prints only the `<svg>`, `-o file.svg`
writes to a file, `--help` lists every option.

**plot** — expressions in `x`: `+ − * / **` (or `^`), `sin cos tan asin acos
atan sqrt abs exp ln log` (`log` = base 10), `pi e`. Options: `--xmin --xmax
--ymin --ymax`, `--xtick --ytick`, `--no-grid`, `--no-legend`, `--xlabel
--ylabel`, `--point "x,y|navn"`, `--vline x`, `--hline y`, `--width --height`
(mm), `--caption`.

**prim** — JSON with `width`, `height` (mm) and `elements`. y grows *downwards*.
Every element accepts `stroke`, `fill` (default `none`), `sw` (stroke width,
0.35 mm default), `dash`, `opacity`.

| `type` | keys |
| --- | --- |
| `line` | `x1 y1 x2 y2` |
| `arrow` | `x1 y1 x2 y2`, optional `heads: start\|end\|both`, `head` (size) |
| `polygon` / `polyline` | `points` — `[[x,y],…]` or `"x,y x,y"` |
| `rect` | `x y w h`, optional `rx` |
| `circle` | `cx cy r` |
| `ellipse` | `cx cy rx ry` |
| `arc` | `cx cy r`, `from`/`to` in degrees (0° = right, positive = clockwise) |
| `angle` | `cx cy r from to`, optional `label`, `label_r`, `size` |
| `dim` | `x1 y1 x2 y2`, optional `text`, `offset` (label offset, mm) |
| `point` | `x y`, optional `label`, `dx`, `dy`, `r` |
| `text` | `x y text`, optional `size` (mm), `anchor: start\|middle\|end`, `weight`, `italic`, `rotate`, `color` |
| `path` | `d` (raw SVG path) |

Example — right triangle with labels:

```json
{"width": 58, "height": 42, "elements": [
  {"type": "polygon", "points": [[4,34],[44,34],[44,10]], "sw": 0.45},
  {"type": "point", "x": 4, "y": 34, "label": "A", "dx": -2.2, "dy": 2.6},
  {"type": "text", "x": 24, "y": 37.4, "text": "b", "italic": true, "size": 3},
  {"type": "angle", "cx": 4, "cy": 34, "r": 8, "from": -33.7, "to": 0, "label": "v"}
]}
```

**Diagram rules**

* Sizes: 55–90 mm wide for a two-column layout, 110–150 mm for full width.
  Height 35–60 mm. Keep the aspect ratio close to the data.
* Stroke-only, white/transparent fill, default ink and accent colours. No
  gradients, no shadows, no dark fills, no bitmap.
* Always give a `--caption`: what is shown, symbols, units.
* Regenerate the snippet instead of hand-editing dozens of coordinates.
* The snippet must stay well-formed XML; `build.py` prints nothing if the SVG
  is broken, but the PDF will show a gap — check the rendered page.

## 7. Build and verify

```bash
python build.py content/Matematik/Retvinklede_trekanter.html
```

Then check:

1. `ok … 1 p` in the output — page count is 1–3.
2. No `!` warnings (missing `<h1>`, own CSS, `<img>`, script, too long).
3. Open the PDF and look at it: no clipped text, no orphan headings at the
   bottom, no diagram wider than the text block, footer shows
   `SUBJECT · Sheet name` (or `SUBJECT/GROUP · Sheet name` inside a group) and —
   only when there are several pages — `2 / 3`.
4. Every formula renders (no empty boxes): MathML mistakes show up as
   unformatted text.

If a diagram is wrong, fix the JSON/plot arguments and regenerate — the HTML
must contain the corrected SVG, not a patched PDF.

## 8. Changing the design

Only when the user explicitly asks for a style change:

* Layout, type scale, spacing, page margins → `factsheet.css` (or `PRINT` in
  `build.py` for margins and page furniture).
* Then `python build.py --force` so every PDF matches the HTML again.
* Never add per-sheet overrides; a sheet must stay pure content.

## 9. Definition of done — always

A sheet is **not** finished when `build.py` prints `ok`. It is finished when the
PDF has been opened and looked at, page by page. Notes are always delivered
complete and checked — never as drafts, half-empty pages or "fix later".

Before a sheet is reported as done:

1. **Build:** `python build.py content/Subject/Sheet.html` gives `ok … 1–3 p`
   and no `!` line.
2. **Look at every page.** Render the PDF pages to images (for example with
   PyMuPDF: `page.get_pixmap(matrix=pymupdf.Matrix(1.15, 1.15))`) and view them.
   Source code and extracted text are not enough: overlaps, clipping and broken
   formulas are only visible on the page.
3. **Check each page for:**
   * text that overlaps, is cut off, or runs past the text block;
   * a fraction or a radical that collides with the line above or below;
   * a formula shown as raw text, an empty box, or a badly drawn root sign;
   * a heading left alone at the bottom of a page;
   * diagrams inside the text block, with a caption;
   * footer `SUBJECT · Sheet name` and `2 / 3` when there is more than one page.
4. **Check the numbers.** Recalculate every worked example and compare stated
   figures with table values (2 260 / 418 ≈ 5,4 — not "seven times").
5. **Fix the HTML and build again.** Never patch the PDF, never leave a known
   error in place.
6. **Report:** state what was reviewed and what was not.

A page that is only half full is not finished either. Fill it with content that
belongs to the topic — another worked example, a table, a diagram, the special
case or the condition of validity. Never with filler, and never by enlarging the
type or shrinking the margins.
